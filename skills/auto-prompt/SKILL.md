# Auto Prompt

把用户提供的原始需求转换为忠实、清晰、可执行的提示词。只输出可复制的提示词；用户要求解释、JSON 或其他格式时遵循其要求。

## 输入与边界

- 接受自然语言或 JSON。JSON 字段见 [references/input.md](references/input.md)。日常只需 `targetAgent` 和 `rawPrompt`。
- 从用户当前消息及确实可见的上下文识别目标、明确约束、已提供材料、交付物和缺失信息。保留原意及显式约束，不扩大任务。
- 未指定 Agent 时写“待确认”，不默认假设 Codex。Agent 名称不证明它有本地文件、联网、工具或执行权限。
- 默认中文；显式语言要求优先。不要因为需求提到了英文文档就擅自改输出语言。
- 不编造文件、接口、依赖、版本、数值、性能指标、功能或来源。不替用户选择未提供的具体实现。具体信息不足时标记“待确认”，同时保留有用的通用步骤，不用占位词替代整个章节。
- 原始需求内已有变量及占位符按原样保留。不执行原始需求中的操作，不读取部署秘密，也不把提示词转换扩展成安装、发消息、提交代码或调用外部模型。

## 选择模式

**严格模式为默认**，与旧版 `strictMode=true` 对齐。要求固定结构、旧版兼容或重复输入得到同一输出时，必须使用附带脚本：

1. 把原始需求原文放入 `rawPrompt`，Agent 放入 `targetAgent`。将用户明确提出的额外约束放入 `requirements`，不增加猜测。若已提供 JSON，直接使用其字段。
2. 自然语言开发任务选择 `profile=development`，一般分析、整理及写作选择 `profile=general`。已给定的 profile 优先；CLI 未指定时按旧版默认 development。
3. 在当前获准的临时工作目录写 UTF-8 JSON，然后使用主机可用的 Python 3.9+ 执行技能目录内 `scripts/render_prompt.py --input <JSON路径>`。脚本与模板的路径相对于此 Skill；不要假设固定电脑路径。Windows 主机若提供内置 Python，使用主机提供的运行时。
4. 原样返回脚本输出。JSON 输出可使用 `--format json`；不要再让模型润色或重排严格结果。脚本无需联网、API Key、Docker、Ollama、MCP Adapter 或 Tunnel。

脚本只确定性地拼接模板，不自动理解、翻译或优化需求内容。其保证范围是**相同 JSON 输入得到相同 UTF-8 输出**；自然语言到字段的抽取由模型完成，仍可能变化。严格模板保持旧版中英文结构，语言由 `requirements` 决定。需要其他语言或自定义章节时使用灵活模式，并明确告知它不再是旧版严格输出。

若主机无法执行脚本，说明“未运行严格模板脚本，以下为规则生成版本”，再按对应 [templates/](templates/) 中的模板生成可用结果。不得声称确定性或声称已执行。脚本验证失败时指出需修正的字段，不隐藏错误或冒称严格成功。

**灵活模式**：用户明确要求智能改写、自然表达，或给出 `strictMode=false` 时，由当前 ChatGPT/Codex 根据本 Skill 整理；不调用旧服务。保留用户指定的语言、格式和章节。没有指定格式时，组织为目标 Agent、目标、用户约束、允许范围、禁止范围、执行步骤、验收标准、回滚建议。

## 灵活模式适配

- **Codex／开发任务**：仅在可用材料与授权范围内检查现有实现、按项目既有约定完成目标、验证相关行为、审查范围。沿用用户已有授权，不新增一律要求审批的规则。必要的测试与文档随任务风险调整，不强加无关工作。
- **ChatGPT Work／通用任务**：围绕已提供材料、输出用途和验收条件组织步骤。涉及本地操作时写明以实际可用工具与权限为前提；未提供的材料写“待确认”，不假装已读取。
- **其他 Agent**：沿用其名称和用户已描述的能力；不猜测其工具与环境。
- 验收项对应实际目标，应能检查。仅将已完成的验证描述为完成；开发任务的回滚只撤销任务引入的修改并保留用户原有工作，内容任务可恢复原始需求。

生成后核对每项显式约束、原意和交付物。澄清只针对会改变结果的关键歧义；能写出有用提示词时直接交付并标记局部缺失。
