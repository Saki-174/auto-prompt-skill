# 对话引导与关键澄清

本文件是 ChatGPT 的行为指导，不是一个宣称所有客户端都实现了的 UI API。

## 工具选择

先检查当前宿主实际提供的工具清单及参数定义：
- 若提供 request_user_input_async 且允许当前场景，使用它；本次开发环境的入口是 functions.request_user_input_async，参数为 questions 数组，每项有 title 和可选的字符串数组 options。问句写完整，建议答案放首位。不要添加工具已提供的“其他”或自由输入占位项。
- 该工具立即返回，回答作为后续用户消息到达。发送问题不等于收到答案，预选项、超时、沉默都不等于用户确认。保留问题，收到答复前不执行依赖该答复的生成步骤。
- 若只提供 request_user_input，先遵守它的当前模式限制与实际 schema；不能在不允许的模式调用它。不同工具的 header/id/options 结构不可混用。
- 若无合适工具、调用失败或宿主只支持文本，直接在回复里给出一个清楚的问题和少量选项；允许用户自由回答或说“暂不确定”。不用额外插件，不伪造按钮或声称提示框已经显示。
- 若用户需要附文件，用普通文字说明所需材料；不要用只接受文本的结构化问题工具索要文件上传。

在确实提供本次 async schema 的环境，单题示例参数如下（先核对可用性，不把示例当通用接口）：
~~~json
{"questions":[{"title":"这段提示词打算交给谁使用？也可以直接输入模型名称或说暂不确定。","options":["ChatGPT","Codex","视频生成模型"]}]}
~~~

## 小步推进

会话内复用字段，不创建隐式持久配置或写入记忆：
1. 记录已确认的目标 Agent、需求、模式及约束，以及待确认项和仅为建议的内容。
2. 选最能改变结果的尚未解决决定。先目标或交付形式，再问依赖它的范围、时长、验收方式。
3. 每轮通常 1 题，最多 2 个彼此独立的问题。简短建议可以放在选项或说明里，明确取舍，不用强烈推荐替用户做决定。
4. 用户修改选择时更新相关字段并废弃被替换的决定；复用仍有效的回答，别从头问一遍。
5. 目标、必要范围和交付物足以形成有用提示词就停止。非关键未知项直接标“待确认”。
6. 连续两轮仍无法确认同一关键项时，给一个可修改的草案或可逆建议，显式列出未知项；允许用户继续澄清，也允许结束。不能以穷尽所有问题为完成条件。

例子：
- “用 ChatGPT 帮我准备面试”缺少岗位，岗位会改变内容，先问岗位；别同轮追问所有题型和排期。
- “给视频模型做个咖啡广告，要高级一点”可先问输出是镜头提示词还是含旁白的分镜；不要先填 4K、24fps 或某模型专属参数。
- “目标 Codex，修复我给出的报错，只改 parser.py，不增依赖”输入已足够转换；无需询问岗位、读者或自选框架。
- “研究这篇文章，200 字摘要，不要外部信息”有完整材料时直接生成；没有文章时标明需提供文章，不假称读过。
