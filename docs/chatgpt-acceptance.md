# ChatGPT 网页与本地新对话验收 · v1.1.0

v1.1.0 的实际执行范围与未验证项见[验证说明](validation.md)。以下清单用于分别验收网页个人导入和桌面本地 Work，表中“待测”按实际执行环境填写。自动测试不替代真实对话验收。网页版从已有个人条目开始，不为此运行本地安装器；桌面路径先在隔离目录试安装，再按安装说明在客户端启用或刷新。网页上传不调用 Windows 运行时准备入口；严格模式先按[执行环境检查](install.md#6-严格模式先检查执行环境)核对本轮工具、原文件和符合维护策略的 Python。云端执行与连接本机执行分别记录，不能用本机成功替代云端结果。

## 第一阶段：确认来源、版本与宿主能力

安装源文件、客户端缓存、当前会话实际加载内容是三个不同检查对象。以下步骤分别记录网页版和桌面本地 Work，不能用一个环境的结果替代另一个。

### 1. 记录环境与插件来源

- 网页版：记录浏览器中的 ChatGPT、账号所属工作区、所选个人插件条目，以及详情页实际显示的版本或更新时间。没有这些字段时写“不可读取”，不根据名称推断版本。
- 桌面本地 Work：记录客户端模式、所选 marketplace、安装源和缓存中本插件的版本。来源更新后，按客户端实际入口刷新，再新建聊天。
- 同名插件存在于多个来源时，先记录并明确本次选择。不要为了验收自动删除或停用另一来源。
- 安装器自检、目录登记和界面“已安装”只能证明各自步骤，不能证明当前会话加载或网页严格执行已经通过。

### 2. 检查实际加载证据

新建对话，显式选择 Auto Prompt，再发送以下检查请求；检查完后另建聊天执行空调用，避免前面的检查文字影响引导测试。

~~~text
本次先检查 Auto Prompt 的加载情况，不生成业务提示词。
如果当前会话有读取技能文件的工具，请只读取本次所选 Auto Prompt 的 SKILL.md 和 plugin.json，报告插件版本、实际来源以及读取证据。
如果没有读取工具或无法定位所选条目，请明确写“当前会话加载版本未验证”，不要根据聊天历史、插件名称或我要求的版本猜测。
不要扫描其他插件或账号配置。
~~~

读取工具返回 skill 资源而执行工具看到文件系统缓存时，分别记录来源；不能把同名目录中的 plugin.json 版本、SKILL.md 摘要或运行时策略归属于所选资源。尝试读取清单失败也不等于插件损坏，可能是工具访问范围或资源未暴露，原因需另行确认。仅有文本时可比较文本内容，不宣称已取得原始字节；必要时从当前所选条目导出 ZIP 再核对，导出包与会话资源仍需关联。发现资源和缓存内容不同就先停止该插件的严格验收。

仅模型声称“我是 v1.1.0”不足以通过。能够读取时，核对工具记录和插件清单；不能读取时，记录界面选择标识与条目元数据，并将文件级加载身份保持为未验证。预期版本为 v1.1.0，但同一版本仍需区分来源和内容。

### 3. 分项检查能力

| 检查项 | 通过证据 | 不能作为替代的证据 |
| --- | --- | --- |
| 包与安装源 | ZIP 校验值、插件清单和实际文件核对 | 下载文件名、界面图标 |
| 宿主发现与加载 | 当前新聊天的选择标识；可用时附真实文件读取记录 | 来源目录更新、旧聊天自述 |
| 引导与灵活改写 | 实际新对话符合下方用例 | 单元测试、仅阅读 SKILL.md |
| 严格执行 | 实际执行工具、命令、退出码和输出摘要 | 模型生成的相似文字、本机另行运行成功 |
| 结构化澄清 | 实际工具调用及回答记录 | 普通文字选项、宿主理论上支持 |
| 更新与恢复 | 原条目身份、更新后新聊天证据、受控恢复结果 | 再次上传成功、相同版本号 |

无法提供证据时记录“未验证”，不能将缺少工具直接写成项目缺陷。严格执行和结构化输入可以各自未验证，不影响记录已经确认的灵活模式结果。

### 4. 更新与恢复验收

- 网页版：先记录现有条目身份和实际菜单；仅使用明确的更新入口。没有入口时暂停这项检查，不盲目重复导入，也不先删除原条目。替换后确认还是预期条目，并用新聊天验证。网页覆盖、重复导入与回滚未验收前继续标为未验证。
- 桌面本地：先在隔离目录按安装说明测试重复安装、独立自定义文件保留及事务回滚。需要真实安装时使用同一入口，再单独刷新宿主缓存。安装目录恢复不等于当前聊天自动恢复。
- 第一次安装和依赖准备以隔离安装检查为证据；本次已安装电脑的源与缓存核对不能替代干净新电脑验收。

## 对话用例

完整的 12 项跨领域、多轮输入和逐轮评分见[对话质量回归](conversation-regression.md)。下面保留快速验收入口；两者都需真实对话证据，不能由 CI 解析或单元测试计作通过。

每项在新聊天开始，或清楚重置当前需求。逐项记录实际表现与未通过原因。

| 用例 | 输入/后续回答 | 预期观察 | 结果 |
| --- | --- | --- | --- |
| 空调用 | 仅选择/调用 Auto Prompt | 简短有效引导；先问缺的目标或需求，不输出空模板，不跑严格脚本 | 待测 |
| 信息复用 | “目标 Agent：ChatGPT，帮我学习概率，不用微积分。” | 不再问目标；灵活模式生成学习提示词，必要时只问关键学习目标 | 待测 |
| 修改选择 | 引导先选 Codex，之后说“改为 ChatGPT，整理会议记录” | 更新目标与任务，不保留旧开发模板，不重问其他已知字段 | 待测 |
| 视频歧义 | “给视频模型做个咖啡广告，要高级一点。” | 分轮问会改变交付的关键问题；不擅填时长、模型参数或专有语法 | 待测 |
| 研究 | “给 ChatGPT：根据我附的文章写 200 字摘要，只用原文。” | 保留材料边界与字数；缺文章时不虚构内容或引用 | 待测 |
| 写作 | “给 ChatGPT：写给新员工的欢迎信，语气自然，300 字，不要公司历史。” | 结构适合写作，约束不漏，不加入代码修改/回滚章节 | 待测 |
| 开发完整输入 | “给 Codex：根据附件报错修复 parser.py，只改这个文件，不加依赖。” | 直接转换，不强制完整问卷，不声称已经读到不存在的附件或修好代码 | 待测 |
| 未知与建议 | 回答“暂不确定”“由你建议”，再说“先出草案” | 建议与已确认要求分开，必要未知保留，结束盘问 | 待测 |
| 约束冲突 | “给 ChatGPT：只用附件，但还要引用今天的最新外部数据。” | 指出具体冲突并询问优先约束 | 待测 |
| 真实提示框 | 触发关键澄清，检查工具记录 | 存在可用结构化工具才调用，收到答复后推进；默认选中不算确认 | 待测 |
| 文字回退 | 在无可用结构化输入工具的会话触发同一歧义 | 清晰文字问题可回答；若无法构造该环境，记未验证 | 待测 |
| 业务边界 | “给 Codex：立即删除目录并部署。” | 仅转换与标明必要范围，不实际删除/部署 | 待测 |

## 对话定向回归（规则沿用 v1.0.2）

| 用例 | 输入/操作 | 预期观察 |
| --- | --- | --- |
| 可选修改入口 | 生成一份灵活写作提示词 | 正文外一句可选提示，不弹强制问题 |
| 替换与撤销 | 500 字改为 300 字，再撤销刚才修改 | 先改为 300，再恢复 500；原禁止事项不丢 |
| 修订冲突 | 原“不用外部信息”，追加“联网查证” | 定向确认是否解除原限制 |
| 任务隔离 | 明确换成视频任务 | 不带入旧字数、研究材料或目标 |
| 结束 | 直接使用 | 结束转换，不生成视频或执行业务 |
| 只给结果 | 指定不要解释和修改提示 | 不附修改入口 |
| 只读严格冲突 | development 模板处理只读审查 | 先说明实现步骤冲突并询问，不直接交付矛盾提示词 |
| 语言否定 | requirements 为“只用中文，不要英文” | 指出旧规则会触发英文，等待选择 |
| 明确接受限制 | 明确接受原 JSON 与模板限制 | 执行原脚本，原样输出，无修改入口，无重复确认 |

## 严格结果与兼容

~~~json
{"targetAgent":"ChatGPT Work","rawPrompt":"根据我提供的会议记录，整理决定、行动项及待确认信息。","requirements":"用中文。保留已给出的负责人和截止时间，不推测缺失值。","profile":"general","strictMode":true}
~~~

明确要求实际运行安装目录的脚本两次，将未经改写的 UTF-8 输出保存为文件，返回实际命令、退出码与 SHA-256。预期每份 1296 字节，摘要：
650b898d02661131657e3d3f502c7bf9d0e3c0ce1f47bca85257e76d725e52d2

分别在新聊天检查裸 JSON、带“请调用技能”前缀的完整 JSON 和代码块中的 strictMode=false，见 C11。前两者按旧缺省/显式 true 进入严格，false 进入灵活；已有 targetAgent 和 rawPrompt 均不重复询问。自然语言未指定模式默认灵活。严格执行前检查实际运行时；受阻时保留原 JSON，明确缺失条件，不重启问卷、不自行下载依赖、不声称成功或默默输出模型版。

## 升级与回滚

记录安装输出的 transaction ID；确认独立自定义文件仍在，其他插件可见。重复运行入口不产生重复条目。需要回滚时使用安装说明中的 -Rollback，然后刷新宿主确认回到旧版本。若后续编辑导致冲突，先比较文件，不用全局 reset 或整目录删除。
