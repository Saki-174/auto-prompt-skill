# 安全与维护

本页包含 v1.1.1 安装权限修复与 v1.1.0 的既有安全保护。最终发布代码以对应版本标签为准；升级时重新下载整合包与校验清单。历史重写前的代码基线映射见[历史定位](history/git-history.md)。

## 安装权限保护：v1.1.1

v1.1.1 修订以 `main / 8ef9655a8d24b44f303b885eafcdccafbbfe51d2` 为开发基线；以下权限保护随 v1.1.1 整合包安装器提供。v1.1.0 附件不包含此修复。

原安装器只核对内容摘要，`shutil.copytree/copy2` 不保留 Windows ACL。宽权限父目录中的私有文件升级后可能变为其他本机用户可读；备份和配置重写存在同类问题。[Python 复制函数限制](https://docs.python.org/3/library/shutil.html)

修订安装器在创建事务目录、原子写入临时文件时就提供仅当前进程账号与 SYSTEM 可访问的受保护 DACL，并在写入内容前核验其生效。备份保留在该私有目录中，备份副本不恢复原有宽权限。程序重建、配置替换与回滚从权限快照恢复原有 owner、primary group、DACL、继承保护标志及 ACE；空的自定义目录也保留。读取、设置或核验权限失败时停止，不请求提权、不放宽原权限。

内容与权限都参与安装前后、目录切换、备份和回滚的检查；仅修改 ACL 的后续编辑或备份变化也会阻止自动恢复。权限快照随 schema 2 事务保存，仅用于本机恢复，包含本机 SID，不应分享事务目录或把它纳入发布包。拥有管理员或 SYSTEM 权限的主体仍可访问这些文件；本措施不防御已控制当前账号的进程。

权限范围限于 owner、primary group 和 DACL，不承诺完整复制 SACL 审计、强制完整性标签、备用数据流或所有文件元数据。Windows 自动继承的 AI/AR 记账标志不参与相等比较；DACL 保护标志和 ACE 的继承位仍参与。恢复使用兼容 API `SetFileSecurityW`，避免较高层设置 API 将私有暂存父目录的 ACE 合入原权限或向子目录传播；每次设置后重新读取核验。[Microsoft API 说明](https://learn.microsoft.com/en-us/windows/win32/api/securitybaseapi/nf-securitybaseapi-setfilesecurityw)

旧 schema 1 事务没有原始 ACL 快照。Windows 下，若需恢复已有文件，修订安装器拒绝自动回滚，要求保留证据并人工处理；此前的内容备份不能推导原权限。升级旧安装仍受支持：新安装器在升级开始时记录现有权限，但不能重建旧安装已丢失的权限。POSIX 路径记录并恢复 mode 位；尚未核验 POSIX ACL、所有者迁移或其他系统的完整权限语义。

实际测试及未验证范围见[权限回归记录](validation.md#安装权限回归-2026-10-09-未发布)。外部持有文件句柄或并发修改父目录的进程仍不受安装器锁约束，应先关闭编辑器与插件管理器；不得将快照复核理解为操作系统级排他事务。

## 输入与文件保护

严格 CLI 在解析前限制 JSON 文件或标准输入为 1 MiB（含 BOM、空白）；`targetAgent` 限制为 256 个 UTF-16 单位。超限、深度过高或无效 UTF-8 输入返回退出码 2。未知字段和重复键采用固定错误说明，不回显原始键名。该策略不使运行日志自动匿名：操作系统错误仍可能包含文件路径，分享前应检查。

已有输出与输入指向同一文件时拒绝写入，包括同路径、符号链接和硬链接。正常文件输出先写同目录临时文件，再原子替换输出目录项；不会截断输出的其他硬链接。这会替换已有输出的文件身份及权限属性，也会替换指向其他文件的输出符号链接本身。输出目录必须已存在，写入失败保留原输出并清理临时文件；不承诺突然断电时的持久性。

安装器将旧目录移到事务 `displaced` 后再次核对内容。检查不一致或无法读取时，活动位置空缺则将该目录移回，报告冲突及事务 ID，不使用较早备份覆盖最新编辑。若活动位置已被其他进程占用，保留事务证据并停止自动恢复。关闭编辑器或插件管理器，检查活动目录和该事务中的 `displaced` 后再重试；不要对冲突事务强行回滚。

这些检查约束安装器自身，不能让所有外部编辑器参与同一事务。持有旧文件句柄的进程仍可能继续写入；更新时应先关闭相关编辑器。普通失败、回滚和冲突的处理见[安装说明](maintenance.md#失败与回滚)。

## 运行时维护

维护复用策略与严格模板兼容性分别管理。检查日期为 **2026-10-08**；安装器、直接 Python 安装入口的运行时登记及 Windows 严格启动器共享 `skills/auto-prompt/scripts/runtime_policy.py` 的策略：

| Python 分支 | 最低补丁版本 |
| --- | --- |
| 3.11 | 3.11.17 |
| 3.12 | 3.12.15 |
| 3.13 | 3.13.16 |
| 3.14 | 3.14.8 |

接受相同分支的后续补丁；不自动接受新分支。已结束支持的 3.9/3.10 和低于表中补丁的解释器不再用于托管安装/启动。直接执行 `render_prompt.py` 没有新增此版本门槛，正常严格输出及旧 JSON 缺省行为仍保留；这不表示推荐在过时解释器上运行。

Windows x64 安装器无法复用符合策略的解释器时，准备项目专属 **Python 3.13.16**。来源为 [Python 官方发布页](https://www.python.org/downloads/release/python-31316/)，文件为 `python-3.13.16-embed-amd64.zip`，约 10.9 MB；固定 HTTPS URL 与完整 SHA-256 见 [runtime-lock.json](../scripts/runtime-lock.json)。保留官方 `LICENSE.txt`，不修改共享 Python、系统 PATH 或注册表。

离线环境需提供符合策略的解释器，或此锁定版本且通过校验的 ZIP；旧 ZIP 不能代替。低于门槛的登记不会导致共享解释器被升级或卸载；重新运行 Windows 安装器会检查并修复。下载/校验失败会停止，恢复方法见[离线安装](maintenance.md#离线与显式运行时)。回滚可能恢复旧程序和旧运行时指针，不代表旧版本满足当前维护策略。

维护者至少每月，以及上游安全发布后复核 [Python 支持状态](https://devguide.python.org/versions/)和各分支官方公告。需要更新时：

1. 从官方发布页核验版本、支持平台、下载链接、SHA-256 和许可；不能只改版本号或绕过校验。
2. 同步策略、锁文件、当前安装说明与候选变更记录，保留标明日期的历史验收结果。
3. 执行边界拒绝、兼容复用、专属运行时联网/离线准备、旧版升级回滚、真实启动器及 32 组旧输出比对。
4. 记录实际环境和未验证范围，完成审查后再发布。

维护一致性测试检查锁定运行时与维护策略、下载坐标、CI 精确版本；不代替官方补丁和校验值核验。候选 CI 增加 Windows 隔离安装、正式 v1.0.2 插件/单技能升级和回滚，只上传结果摘要，不上传运行时、配置或完整日志。未提交或未实际运行的 CI 不计作通过。

固定校验值保证取得预期文件，不保证版本永久安全；本项目没有增加后台自动更新服务。

## CI 依赖

CI 的 `checkout`、`setup-python`、`upload-artifact` 固定为完整提交 SHA，旁边保留对应主版本注释，权限继续为 `contents: read`。本次 SHA 来自对应 `actions/*` 官方仓库的标签解析；这固定执行内容，并不等于对 Action 全部代码的独立审计。依据：[GitHub 安全使用指南](https://docs.github.com/en/actions/reference/security/secure-use)。

更新时先核对官方仓库、发布说明及标签解析的完整 SHA，再改引用和注释，通过对应提交的四组矩阵 CI 和 Windows 安装检查后分发。CI 明确使用 Python 3.13.16 和 3.14.8，避免 Runner 复用低于维护门槛的缓存版本；更新补丁策略时同步检查 CI 版本。`ubuntu-latest`/`windows-latest` 仍会随托管平台变化，本地测试不能代替远端 CI。

## Git 元数据与防误提交

`.gitignore` 增加私钥和证书容器的常见扩展名及 SSH 私钥文件名；它只阻止部分未跟踪文件的误提交，不能隐藏已跟踪文件或 Git 历史。

未来提交可使用 GitHub 账号设置提供的 noreply 邮箱。在仓库根目录运行以下命令前，必须把占位文字替换为账号实际提供的地址：

```powershell
git config --local user.email '替换为你的GitHub-noreply邮箱'
```

安装器不自动修改 Git 身份配置。2026-10-08 的邮箱清理已更新本地及远端提交/标签身份，当前克隆使用 noreply；旧 SHA 的公开入口仍未完全清除，见[映射与剩余边界](history/git-history.md)。进一步历史操作应协调引用和旧克隆，不能以忽略规则或当前 refs 已更新宣称旧信息消失。公开文档不展示原始邮箱。
