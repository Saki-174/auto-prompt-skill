# 使用与模式

[文档导航](README.md) · [安装教程](install.md) · [运行逻辑](runtime.md) · [输入协议](../skills/auto-prompt/references/input.md)

## 开始一项任务

在已启用 Auto Prompt 的 ChatGPT 新聊天中，选择实际插件或技能后发送：

~~~text
请使用 Auto Prompt。
目标 Agent：ChatGPT
需求：帮初学者学习概率，先用生活例子解释，再给两道练习题。
约束：用中文，不使用微积分，先不附答案，等我作答再批改。
~~~

预期得到可复制的教学提示词，而不是概率课程。也可以只发送`请调用 Auto Prompt 技能`，按引导补充缺少的信息；完整输入不需要重新填写问卷。

运行宿主是加载技能的 ChatGPT 环境；目标 Agent 是接收生成结果的工具。给 Codex 的需求可以说明文件和允许修改范围；学习、写作和视频需求按实际交付描述，不必套开发流程。未知目标的专有参数、格式和能力不会凭名称补齐。

## 补充与修改

| 在聊天中说 | 预期行为 |
| --- | --- |
| `追加……` | 合入新增要求；与旧要求冲突时先确认冲突 |
| `把……替换为……，其他不变` | 替换指定部分，保留未修改的约束 |
| `撤销刚才修改` | 撤销上一轮修改，返回恢复后的完整提示词 |
| `换个任务` | 整理新任务，不沿用前一个任务的专属事实或约束 |
| `直接使用` | 结束转换，不代为执行业务任务 |

可以回答`暂不确定`、`由你建议`或`先出草案`。建议应与已确认要求分开。关键歧义分轮询问；非关键缺口可标待确认。宿主有适用的结构化输入工具时使用它，否则文字提问，不要求额外插件才能基本使用。

首次灵活输出可附一句可选修改入口；严格输出、后续修订和“只给结果”时省略。普通结果应能完整复制，只有实际补丁或明确要求差异格式时才使用 diff。

## 灵活模式

自然语言对话默认灵活模式，由当前宿主模型理解和改写；相同需求的措辞可能随模型和上下文变化。优先保留数量、单位、对象、限制强度和权限范围，不把建议伪装成要求。技能只转换提示词，默认不执行其中的任务。

## 严格模式

明确选择严格模式后，由包内 Python 脚本和中英文开发／通用模板固定渲染。在固定脚本和模板下，相同 JSON 得到相同 UTF-8 输出。自然语言抽取 JSON、理解原意和目标 Agent 执行结果不在这一保证内。

完整旧 JSON 缺省`strictMode`仍按`true`；`strictMode=false`由宿主灵活改写，离线脚本不负责该模式。直接 CLI 的旧参数和默认值保留。字段、命令和语言限制以[输入参考](../skills/auto-prompt/references/input.md)为准；合成 JSON 位于[examples/](../examples)。

严格模式不自动理解或翻译任意需求。例如“不要英文”可能触发旧英文关键词规则，只读任务也可能与开发模板的实施步骤冲突。技能应先澄清，不擅自改 JSON；直接 CLI 不做语义澄清。脚本或合规运行时不可用时必须说明未执行，不能把灵活草案称为严格结果。

本机执行证据和网页云端能力分别记录。网页先完成[严格模式环境检查](install.md#6-严格模式先检查执行环境)，其他边界见[验证说明](validation.md)。

## 验收自己的使用环境

先按[来源与宿主清单](chatgpt-acceptance.md)检查所选技能和执行文件的关联，再检查引导、生成、修改撤销和换任务。自然语言结果符合预期不单独证明插件已加载；本地脚本成功不证明云端可执行。
