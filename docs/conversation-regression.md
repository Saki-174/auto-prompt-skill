# 对话质量回归

对应 v1.1.0 行为基线，使用[12 项合成用例](../tests/fixtures/conversations.json)检查真实宿主和模型输出。文件解析成功不代表对话通过；不需要模型 API 或额外服务。

## 执行步骤

1. 按[来源与能力验收](chatgpt-acceptance.md#第一阶段确认来源版本与宿主能力)记录宿主、聊天/Work 模式、模型可见标识、插件来源及加载证据。模型自述不单独证明加载。
2. 每个用例新建聊天，各轮留在同一聊天；C11 的输入形式变体例外，各自使用新聊天；只提交 input，不把 expected_action、checks 或其他测试答案交给被测模型。
3. 按实际工具和权限执行。没有执行权限或加载受阻时记未运行/阻塞，不购买套餐、不改全局配置。
4. 首轮优先 C01、C02、C05、C09、C10、C11，环境可用后覆盖全部用例。重要用例在新聊天重复，保留每次结果，不选择性丢弃失败轮次。

## 逐轮评分

检查需求/数字/范围是否保留、未改的约束是否仍有效、有无虚构事实或授权、结构是否适合领域、澄清和修订是否正确、工具与执行陈述是否有证据。允许措辞和章节变化，不以关键词匹配代替语义判断。

| 状态 | 条件 |
| --- | --- |
| 通过 | 加载与真实对话有证据，本轮全部 checks 满足 |
| 失败 | 实际执行出现约束遗漏、虚构、错误修订、污染或虚假执行陈述 |
| 未运行/阻塞 | 没有响应，或权限、服务、加载等前置条件不满足 |
| 未验证 | 只有推演、自述或普通模型表观行为，缺少必要证据 |

约束遗漏、编造事实/授权、跨任务污染、把未执行脚本称为严格成功属于阻断项，不以其他通过轮次抵消。C11 在无脚本工具时如实说明未执行可满足该分支的行为要求，但严格执行能力仍未验证。

C11 的真实脚本输出应为 1296 字节，SHA-256 为 650b898d02661131657e3d3f502c7bf9d0e3c0ce1f47bca85257e76d725e52d2。自然语言抽取不在确定性保证内。

每次记录日期、提交/候选说明、宿主与模式、模型标识（不可见则未知）、加载证据、用例与轮次、实际输入输出、工具记录、逐项结论和原因。原始对话留在私有工作目录，公开说明只保留合成案例与必要脱敏结果，不上传账号配置、凭据或浏览器原始日志。

## 手工回传与用例校准

手工回传按两层记录：先记录可见文字是否满足约束，再记录加载、执行和工具证据是否足以判为宿主通过。正文符合不等于脚本执行、提示框回退或所选技能已加载；完整结果中的未知来源继续保持未验证。

- C10 首轮缺少研究主题且 500 字的作用对象不明，合理澄清不算错误。补充主题与篇幅范围后，再单独检查未知 Agent 的通用草案；不能只看模型名称就认定兼容。
- C12 区分“直接给待确认草案”和“先在当前对话澄清”。新版首轮明确要求实际提问，第二轮要求草案。下游提示词里写了问题，不等于本轮已向当前对话提问；有/无结构化工具分支分别记录。
- 除明显遗漏，还检查限制强度和对象是否变化，例如“200 字”被放宽为“200 字左右”、样本改称人数、只读扩大为禁止所有检查。新增格式和权限建议不能伪装成已确认要求。

本轮原始回传对应校准前输入，新增轮次尚未执行；修改测试预期不能追溯地把旧结果标为通过。观察汇总见[Work 对话记录](validation.md#work-手工对话回归与最小修订2026-10-09)。
